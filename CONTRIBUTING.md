# Contributing to NEXUS AI

Thank you for your interest in contributing to NEXUS AI. This codebase is designed as an enterprise-grade AI SRE platform.

## Development Principles

1. **Causal Simulation Integrity**: Never hardcode incident outcomes or telemetry timelines. Faults must be injected only at the root node, and observable symptoms must emerge causally from the $M/M/1$ queueing network.
2. **Honesty Labels (`provenance`)**: Every metric, calculation, and UI component must be labeled accurately:
   - `REAL`: Authentic computation (statistical models, distance metrics, rankers, optimization, benchmarks).
   - `SIMULATED`: Synthetic generation representing physical infrastructure (telemetry queues, logs, deploy events).
   - `PRODUCTION-GAP`: Real-world components that would replace simulated parts in production (e.g., OTel collector, Kafka, Vector DB).
3. **No Metric Fabrication**: Do not hard-code evaluation scores. All numbers rendered on the Evaluation page must be generated by `nexus.evaluation.benchmark` at runtime with Wilson confidence intervals.
4. **Separation of Concerns**:
   - API endpoints must not contain ML fitting logic.
   - Simulation modules must remain decoupled from HTTP/SSE transport.
   - Agent tools must inspect genuine state rather than reading injected fault definitions.

## Repository Layout

- `backend/nexus/simulation/`: Queueing network simulator, topology graph, incident scenarios.
- `backend/nexus/ml/`: Harmonic baselines, AR(1) whitening, Ledoit-Wolf Mahalanobis, IsolationForest, CUSUM changepoints, feature extraction, RCA classifier.
- `backend/nexus/rag/`: BM25 + TF-IDF/SVD latent semantic retrieval with Reciprocal Rank Fusion over runbooks.
- `backend/nexus/agent/`: 15-stage incident orchestrator, inspection tools, policy gate, human approval.
- `backend/nexus/evaluation/`: Multi-episode benchmark harness, auditable metrics, Wilson CIs.
- `web/`: Next.js 16 frontend with real-time SSE streams and SVG service graphs.

## Workflow

1. Fork and clone the repository.
2. Run `make setup` or execute `python scripts/setup/setup.py`.
3. Verify test suite with `make test`.
4. Run `make quick` to ensure the benchmark harness executes end-to-end without errors.
5. Create your branch: `git checkout -b feat/your-feature`.
6. Ensure `make lint` and `make test` pass before opening a Pull Request.
