## 8. Three-minute technical demo script

**0:00–0:20 — Landing.** "NEXUS AI: autonomous incident intelligence. Four claims — a causal simulation rather than an animation, statistics before LLMs, evidence-ranked root cause, and everything measured. Note the honest-scope panel: I label what's real, what's simulated, and what a production deployment would replace. Those labels also appear on every panel inside the product." Click **Launch demo**.

**0:20–0:50 — Command Center.** "This is live — Server-Sent Events, one tick every 0.6 real seconds representing fifteen simulated seconds. Health is a weighted SLO score. The middle panel is the fused anomaly score against its threshold; the threshold is the 99.5th percentile of the score distribution over twenty-six hours of clean warm-up history, so it's derived, not tuned by hand. The service table is sorted by anomaly score and shows the top contributing z-scores per service. Everything is quiet right now — that matters, because a detector that fires constantly is worthless." Point at the scenario library. "Seven reproducible faults. I'll let it pick one at random so I can't cherry-pick." Click **Simulate incident**.

**0:50–1:20 — Detection.** "The fault is now injected into the environment. Watch the anomaly score climb past the dashed threshold — and notice it doesn't open an incident on the first breach. There's a three-of-five persistence gate with hysteresis, because single-tick spikes are noise. Now the gate is satisfied and an incident opens automatically." Auto-navigate to Investigation.

**1:20–2:10 — Investigation.** "Fifteen stages, each one a real computation. Localization first: six services are breaching, but blame ranks Postgres at the top — that combines anomaly magnitude with CUSUM onset lead, because causes move first, and with upstreamness measured on the anomalous subgraph, because the cause is the node the other victims depend on. Without that term the system just blames the gateway, which is always the loudest and almost never the cause.

Hypotheses: seven candidate classes ranked by a logistic regression over thirty features, with per-feature contributions — coefficient times standardized value — so you can see that `leader_kind_datastore` and `log_lock_wait` drove it, and `deploy_on_leader` argued against a bad release. There's an independent rule-based cross-check underneath; when the two rankers disagree, the UI says so.

Retrieved evidence: hybrid BM25 plus LSA retrieval with rank fusion pulled the Postgres latency runbook. Critically, the recommended action comes out of that document's action manifest — the system can only propose actions that exist in retrieved documentation.

Impact: SLO breaches, error-budget burn, revenue at risk. The dollar figure is computed from measured excess error volume times a stated per-request revenue assumption, and I say that in the panel rather than presenting it as a measurement."

**2:10–2:40 — Approval and verification.** "Policy engine: medium risk on a SEV1, so it will not execute. This is a real asyncio gate — the workflow is blocked on my decision. I'll approve." Click. "That mutates the actual fault object in the environment. Now the detector independently verifies: it needs six consecutive ticks below threshold before it will close. Health climbs, the incident closes, and we get a simulated MTTR." *(Optional 15-second version: reject and approve a wrong alternative instead — "the system doesn't recover, verification fails, and it escalates rather than declaring victory.")*

**2:40–3:00 — Evaluation.** "And the reason to believe any of this. This page is generated by a benchmark harness that replays labelled episodes through the same code: detection F1 and PR-AUC with false positives per clean episode, localization top-1 through top-3 with per-scenario breakdown, root-cause accuracy under GroupKFold cross-validation grouped by episode seed with a confusion matrix and calibration bins, retrieval quality reported twice — once with an oracle query to isolate the retriever and once end-to-end — and Wilson intervals on everything because the sample is small. If the harness hasn't run, this page shows an empty state instead of placeholder numbers. The synthetic caveat is on the About page: these measure my generative process, so treat them as an upper bound."
